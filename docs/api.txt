1. хранение и консоль
- все данные во время работы хранятся в памяти (коллекции), без БД +
- цикл чтения команд из консоли
- служебные команды: help, logout, exit

2. пользователи
- регистрация: логин + пароль, логин уникальный +
- авторизация по логину и паролю +
- несколько пользователей +
- пользователи тоже сохраняются в файл, иначе после перезапуска не войти

3. операции, категории, бюджеты
- добавление дохода и расхода: категория + сумма
- создание категорий
- бюджет (лимит) на категорию расходов, необязательный
- бюджет бессрочный: остаток = лимит - все расходы по категории

4. кошелек
- привязан к пользователю +
- хранит баланс, все операции, категории и бюджеты

5. вывод информации
- общая сумма доходов и расходов
- суммы по каждой категории
- по каждому бюджету: лимит и оставшийся бюджет
- вывод в терминал или в файл

6. подсчет по нескольким категориям
- категории через запятую (в названиях бывают пробелы)
- найденные считаются, про ненайденные сообщение "категория не найдена"

7. валидация (везде, не только при входе)
- сумма: число, больше 0
- пустые логин, пароль, названия
- несуществующая категория
- неизвестная команда, неверное число аргументов
- понятное сообщение вместо падения программы

8. оповещения
- превышен лимит бюджета по категории
- расходы превысили доходы

9. сохранение и загрузка
- при авторизации загружать кошелек из файла
- при выходе (logout / exit) сохранять кошелек в файл
- формат JSON, не properties: данные вложенные (списки операций)

10. переводы между кошельками (доп. задание)
- получатель ищется по логину, uuid не нужен
- у отправителя расход, у получателя доход
- если получатель не в сети: загрузить его кошелек из файла, изменить, сохранить
- проверки: получатель существует, не самому себе, сумма больше 0

11. команды
register <логин> <пароль>
login <логин> <пароль>
add-category <название>
add-income <категория> <сумма>
add-expense <категория> <сумма>
set-budget <категория> <сумма>
stats
stats <кат1>, <кат2>
report <файл>
transfer <логин> <сумма>
help
logout
exit
